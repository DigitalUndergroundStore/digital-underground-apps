# Changelog Kit
Turn every release into a reason for users to come back.

## Version naming
- MAJOR.MINOR.PATCH (2.3.1): major = breaking/big new thing, minor = feature, patch = fixes.
- Or date-based (2026.10.26) for continuously shipped web apps.

## Changelog entry format
### v[1.4.0] — [YYYY-MM-DD]
**New**
- [Feature] — [why it matters to the user, one line]
**Improved**
- [Thing] is now [faster/simpler] ([number if you have it])
**Fixed**
- [Bug users noticed], thanks @[reporter]

Rules: write for users, not commits. Lead with the most visible change. Credit reporters.

## Release note (in-app / site, ~60 words)
**[Product] [version] is here.** You can now [headline feature]. We also [improvement] and fixed [notable bug]. Thanks to everyone who sent feedback — keep it coming at [contact].

## X post (feature)
New in [Product]: [feature] ✨
[1 line on the pain it removes]
[GIF/screenshot]
Update now / try it → [link]

## X post (fix roundup)
[Product] [version]: 🛠 [n] fixes, ⚡ [speed gain], 🙏 thanks @[user] for the reports. Full changelog → [link]

## LinkedIn update
We shipped [Product] [version] this week.
The biggest change: [feature] — because [customer insight].
Also: [improvement], [fix].
Small, steady releases > big rare ones. What should we build next?

## Email to users
Subject: [Product] now [does X]
Hi [first name],
Quick update: [Product] [version] adds [feature], so you can [outcome].
Also new: [item], [item].
Reply to this email with anything that bugs you — I read every one.
— [Your name]

## Cadence checklist
- [ ] Changelog page updated the same day
- [ ] One post per meaningful release (not per patch)
- [ ] Monthly roundup email
- [ ] Screenshot/GIF for every "New" item
