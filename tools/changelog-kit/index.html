# Changelog Kit
Turn every release into a reason for users to come back.

## Version naming
- MAJOR.MINOR.PATCH (2.3.1): major = breaking/big new thing, minor = feature, patch = fixes.
- Or date-based (2026.10.26) for continuously shipped web apps.

## Changelog entry format
### v[1.4.0] — [YYYY-MM-DD]
**New**
- [Feature] — [why it matters to the user, one line]
**Improved**
- [Thing] is now [faster/simpler] ([number if you have it])
**Fixed**
- [Bug users noticed], thanks @[reporter]

Rules: write for users, not commits. Lead with the most visible change. Credit reporters.
